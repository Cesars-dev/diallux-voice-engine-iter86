## 1. What V6.7 adds (the SlotConfirm gate)

Clone of V6.6 plus one new state inserted between Booking and Closing:

```
Booking (slots + confirm ritual + NAME GATE)
   ├─ selected_time + prospect_timezone populated ──→ SlotConfirm
   └─ booking_failed (double calendar outage) ──────→ Closing (wrap-up)
SlotConfirm ("One moment while I confirm that.")
   ├─ create_livecall_booking
   ├─ record_booking_uid        (uid from response JSON → dv, verbatim only)
   ├─ validate_booking          (CODE tool: names/company/selected_time present,
   │                             callback E.164, tz IANA incl. America/Phoenix,
   │                             uid ≥ 6 chars → {valid, problems})
   ├─ valid:true  → extract_slot_result(booking_verified=true) → transition_to_Closing
   └─ valid:false → recoverable (missing names → ask once → revalidate)
                    or hard (no uid after retry → booking_failed=true → end_call)
```

The transfer boolean is **hard-gated**: no `booking_verified=true` without a code-tool pass over non-null schema-clean values + a real calendar uid. This kills the phantom-booking class (Gene V6.5's fake-slot insistence) *by construction*, not by prompt hope.
