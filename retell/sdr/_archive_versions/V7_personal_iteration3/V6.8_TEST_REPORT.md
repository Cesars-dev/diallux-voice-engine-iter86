## Architecture shipped (owner topology, verbatim)
```
Intake → Discovery → Closer → Offer → contact_details → ConfirmSlots → Booking → Closing
```
- **ConfirmSlots**: filler phrase → date/slots → confirm ritual (untouched placeholder style) → **3-tool gate**: capture (`extract_confirm_details`) → `verify_info` CODE (regex/E.164-suggestions/enum/non-null; suggestion ⇒ problem ⇒ data_complete=false) → `slot_verified` copy-extract. Edge to Booking requires `[slot_verified, selected_time, prospect_timezone]`. Runaway valve: ~10 passes → polite server-trouble close.
- **Booking**: "just books" — create → record uid → validate → `record_booking_outcome(booking_verified)` → Closing; fail×2 → booking_failed → polite end. **1674 tokens** (was 2481).
- Contact extract split semantic: person[3] + reach[2]; number contract: injected E.164 default, upsert only on alternate-or-suggestion.
