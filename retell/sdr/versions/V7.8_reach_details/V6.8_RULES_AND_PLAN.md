## Architecture (owner's topology)

```
Intake → Discovery → Closer → Offer → contact_details → ConfirmSlots → Booking → Closing
                                        (number contract)  (3-tool gate)  (just books)
```

- **ConfirmSlots** (new, HVAC-slot_selection-style): filler *"one moment while I check availability"* → `check_current_date` + `query_livecall_slots` → `{{requested_slot}}` mapped from response (`response_variables`, verbatim) → confirm ritual (existing `[DAY] [TIME A] [OPTION 1]` placeholder style, UNCHANGED) → 3-tool gate → `slot_verified=true` → edge to Booking.
- **Booking** (slimmed): receives verified data; `create_livecall_booking` + `record_booking_uid` + final validate; "booking just books." My V6.7 SlotConfirm state is DELETED.
- **Gate rule:** never transition on garbage. Edges are soft (`""` passes); the code verdict is the only hard guarantee.

## The 3-tool deterministic gate

| Tool | Type | Job |
|---|---|---|
| T1 capture | native extract, **≤4 fields each, split semantically** | person: first_name/last_name/company · reach: callback_number/is_calling_best_number (+tz stays its own enum tool). Context-first fill; ask only when truly absent. |
| T2 `verify_info` | **code** | reads dv only. Enforces E.164 regex, name presence, `[surname_not_provided]` allowed, tz IANA enum, requested_slot non-empty. Returns `{data_complete, problems[], suggestions{}}` — computes fixes itself (e.g. `(312) 555-1234` → `+13125551234`). |
| T3 boolean setter | native extract `slot_verified` | description: *"set true ONLY when verify_info returned data_complete:true."* LLM triggers it, **code decides the verdict**. Edge requires it. |

**Loop:** fill(T1) → verify(T2) → false? upsert T2's suggestions verbatim → recall. True is absorbing.
**Runaway valve:** ~10 failed passes → *"We're having temporary issues on our server — I'll register your appointment and we'll confirm shortly"* → polite close. Lead never dropped.
**Build-time probe:** test whether code tools support `response_variables` (direct dv write). If yes, T2 may write `slot_verified` itself; T3 remains the fallback.

## Field rules

- `callback_number`: injected E.164 at go-time (caller-id / dynvar seeds). Upsert ONLY when `is_calling_best_number=false`. Tool desc: *"Populated from the user's call number…"* — no webhook jargon. Prompt asks for a plain 10-digit number; T2 normalizes to E.164 and suggests back.
- Number confirm: ONE read-back confirmation (*"So that's 312-555-1234, correct?"*). **No slow digit-by-digit theater** — speech normalization handles pacing.
- Names: first_name required · last_name asked-but-optional · `[surname_not_provided]` marker accepted by T2. Refusal fallback: book under `{{company_name}}`, reason in booking notes. Never drop a lead over a name.
- Extract tool hygiene: ≤4 variables per extract tool, semantic grouping only.

- Only scrub in all of V6.x: the two `(confirmed contact number)` tails (contact_details.md:2, Booking.md:2).
